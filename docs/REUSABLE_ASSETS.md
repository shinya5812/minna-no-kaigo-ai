# REUSABLE_ASSETS.md — 再利用可能な資産の棚卸し

「みんなの介護AI」プロジェクト凍結（2026-06-17）にあたり、他プロジェクトへ
流用する際の観点で構築済み資産を棚卸しする。詳細な経緯は `PROGRESS.md` 参照。

---

## 1. PDF生成の仕組み

- **何か**：fpdf2ベースのPDF生成スクリプト。表紙／はじめに／プロンプト
  ページ／アップセル／締め、をテンプレートメソッド構造で組み立てる。
  日本語フォントはBIZ-UDGothicを使用。
- **どのファイルか**：`scripts/generate_pdfs.py`
- **流用可能なプロジェクト**：「プロンプト集をPDFで売る」系の商材全般
  （業種を問わず、PDF直販モデルであれば流用可能）
- **流用時の注意点**：
  - 日本語の折り返し挙動に癖がある。`「※` の直後に半角スペースを
    入れるとfpdf2がそこをワード境界と誤認し行末に孤立させる
    （2026-06-09に発見・対処済み。半角スペース除去で解消）
  - 長いプロンプト本文がページをまたぐ際、入力例・出力例のブロックが
    次ページに孤立して空白ページになることがある。`get_y()` を見て
    しきい値（実績値：155）を超えたら`add_page()`する改ページ判定が必要
  - 上記2点は個別の商材テキストに依存するため、流用先でも同種の
    レイアウト崩れが起きないか必ず目視確認すること

## 2. トップページの心理導線設計＋Next.js/Vercel構成

- **何か**：非IT層・アナログ拒否反応層向けの心理導線を組んだトップページ。
  構成順は「共感→不安解消→価値提示（1入力→複数出力の展開見せ）→
  使い方3ステップ→料金→FAQ」の6セクション。
- **どのファイルか**：`app/page.tsx` と以下のコンポーネント
  - `components/hero.tsx`（共感）
  - `components/pain-points.tsx`（共感）
  - `components/ai-anxiety.tsx`（不安解消）
  - `components/before-after.tsx`（価値提示：1入力→複数出力の展開）
  - `components/three-steps.tsx`（使い方3ステップ）
  - `components/pricing.tsx`（料金）
  - `components/faq.tsx`（FAQ）
- **流用可能なプロジェクト**：アナログ層・非IT層向けの商品LP全般
  （ターゲットが「便利さより先に不安を解消する必要がある層」の商材）
- **流用時の注意点**：
  - この並び順自体が説得の設計（先に価値を出すと不安解消前に離脱する）
    なので、セクションの順序を入れ替えると効果が落ちる可能性が高い
  - コピーは介護職向けに最適化されているため、業種を変える場合は
    「不安解消4カード」「Before/After」の文言を丸ごと書き換える前提

## 3. プロンプト設計パターン

- **何か**：
  - 「1メモ→複数文書同時生成（宛先別に書き分け）」型のプロンプト構造
    （記録パックの核。1つの事実入力から介護記録／申し送り／家族報告の
    3様式を同時生成し、宛先ごとに文体を変える）
  - 入力欄は空欄でなく記入例を埋めておく方式（非IT層の入力ハードルを
    下げ、書き換えるだけで使えるようにする）
  - AI免責の設計思想：「事実を作らない」と断言しない
    （実際のAIは要約・言い換え・補足を行うため断言は信頼崩壊のリスク。
    「最終確認は利用者の責任」と正直に促す設計）
  - 生成型プロンプト（想定問答等、事実ベースが薄く生成寄りの文書）には
    「（準備案）」「（要確認：〇〇）」マーカーを自動付与し、断定を避けて
    購入者を保護する
- **どのファイルか**：`scripts/generate_pdfs.py` 内のプロンプト定数群
  （記録パック5本・コンプラパック7本の本文・入力例・出力例）
- **流用可能なプロジェクト**：「AIで書類作成を補助する」系商材全般
  （介護に限らず、複数宛先向け文書を1入力から生成する業務全般に応用可）
- **流用時の注意点**：
  - 「入力に書かれていないことは、想像で付け足さないでください」の
    制約文は必須。付与漏れがあると生成物の事実誤認リスクが上がる
  - 免責注記の自動追記（プロンプト本文に「【ルール】出力末尾に必ず...」
    形式で埋め込む）は、書類の性質上リスクが高いもの
    （実地指導・想定問答など）にのみ付与する設計だった。全プロンプトに
    一律で付けると冗長になるため、書類の性質ごとに要否を判断すること

## 4. 3層プライシング設計の考え方

- **何か**：無料（集客の入口）／中価格（複合化で差別化）／高価格
  （競合不在の課題解決型を主力に据える）の3層構成。価値と価格を
  一致させる原則（価値が高いものを安く売らない）を徹底。
- **どのファイルか**：`components/pricing.tsx`（実装）／
  `PROGRESS.md` 2026-06-02「価格・パッケージ再設計と戦略確定」（設計根拠）
- **流用可能なプロジェクト**：情報商材・テンプレ集・プロンプト集など、
  松竹梅の価格帯で購買心理を設計するデジタル商品全般
- **流用時の注意点**：
  - 価格設定の前に必ず「商品ごとの価値の棚卸し」を行うこと。本プロジェクト
    では旧価格が価値と逆相関していた（安い方が価値が高い）ことが発覚し、
    販売開始前に是正した経緯がある（`PROGRESS.md` 2026-05-30参照）
  - 中価格帯は無料版との差別化が必須条件になる。差別化要素
    （本プロジェクトでは「複合化＝1入力→複数出力」）を用意できない場合、
    3層構成自体が成立しない
